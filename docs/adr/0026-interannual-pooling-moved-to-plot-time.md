# Interannual pooling moved from estimate_flexibility_needs.py to plot_flexibility_needs.py

**Status**: accepted

## Context

[0023](0023-interannual-flexibility-needs-batched-compute.md) had `estimate_flexibility_needs.py` write an already-*pooled* `interannual_flexibility_needs.csv` - one need/provision number per (source scenario, run_type, group). Two problems surfaced running this for real against 39 R2050 weather years:

- `estimate_flexibility_needs.py` is the pipeline's genuine bottleneck (multi-day for a full weather-year sweep - confirmed directly: even a 5-folder local test took ~10 minutes). Its own per-scenario GDX read is the expensive part; the pooling arithmetic itself (`_interannual_rows`, half-summed-absolute-deviation over a handful of floats) was always microseconds, but living inside this script meant *any* change to what gets pooled required re-running the whole expensive thing.
- A single erroneous weather year can dominate a pooled number without any way to detect it from the CSV - confirmed directly: `illustrate_interannual_flexibility_needs.py` ([0025](0025-interannual-illustration-reuses-per-folder-cache.md)) revealed one weather year (1985) at +300,000 MW against every other year's ~-230,000 MW, which alone was responsible for most of a 4767.81 TWh/a Interannual need. Neither `flexibility_needs.csv` nor `interannual_flexibility_needs.csv` retained the per-year values needed to catch this - only the illustration, generated by hand for one specific group, happened to surface it.

## Decision

- `estimate_flexibility_needs.py` now writes **`interannual_annual_means.csv`** - one row per (source_scenario, run_type, weather_year, group_type, group, category, commodity, flex_option) holding the *raw* `annual_mean_mwh` scalar, not a pooled number. `_interannual_rows` (the pooling function) is gone from this script entirely, replaced by `_interannual_annual_mean_rows`, a pure flatten with no need/provision arithmetic at all.
- **Pooling moved to `plot_flexibility_needs.py`** - a new `_pool_interannual` there, identical math to the old `_interannual_rows` (same need/provision/sign/Other-catch-all construction, same F/R-collision-avoiding `Scenario` naming from 0023), just DataFrame-driven since the input is now a flat CSV rather than an in-memory accumulator. `HOURS_PER_WEATHER_YEAR` moved with it (own copy, matching this script's existing GDX-independence pattern for `WEATHER_YEAR_RE` etc. - importing it from `estimate_flexibility_needs.py` would drag that module's `pybalmorel` import chain into a script that deliberately has none).
- New `--exclude-weather-year source:year[:run_type]` (repeatable) on `plot_flexibility_needs.py` drops matching rows from `interannual_annual_means.csv` before pooling. **Warn-only by design, no automatic exclusion** - the user explicitly rejected auto-excluding outliers: a rare, genuinely extreme weather year is exactly the kind of signal this whole feature exists to surface, so an automatic threshold risks quietly discarding real science along with genuine errors. A human names exactly which weather year(s) to drop, after looking at the data (the illustration script, or the raw `interannual_annual_means.csv` itself, both now sufficient to catch this class of problem directly).
- `illustrate_interannual_flexibility_needs.py` ([0025](0025-interannual-illustration-reuses-per-folder-cache.md)) still recomputes its own pooling straight from `.gdx_cache`, never reads either interannual CSV - unaffected by the file-format change above. It did gain the same `--exclude-weather-year` (accepting a bare `year`, since this script's own `--source-scenario`/`--run-type` already fix which pool it's illustrating, as well as `plot_flexibility_needs.py`'s `source:year[:run_type]` shape, so one exclusion list copy-pastes between both tools) - for the same warn-only, human-in-the-loop reason as `plot_flexibility_needs.py`'s own flag.

## Considered options

- **Auto-exclude weather years past a statistical threshold** (e.g. z-score/IQR). Rejected per the user's explicit direction above.
- **Keep pooling in `estimate_flexibility_needs.py`, just also write the raw per-year values as a companion audit file.** Solves detectability but not the actual cost problem - re-pooling after excluding a bad year would still require re-running the multi-day script to get a corrected `interannual_flexibility_needs.csv`, even though the pooling step itself was never what made it slow.

## Consequences

`interannual_flexibility_needs.csv` no longer exists - anything reading it directly (none, in this repo) needs to read the raw `interannual_annual_means.csv` and pool via `plot_flexibility_needs.py`'s `_pool_interannual` instead, or invoke that script.
